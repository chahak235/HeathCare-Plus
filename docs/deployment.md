# Deployment

The live setup is three free services:

| Part | Host | What it runs |
|------|------|--------------|
| Website | **Vercel** | `frontend/` (Vite + React), including the X-ray model file |
| API | **Render** | `backend/` (Node 22 + Express), Singapore region |
| Database | **Neon** | PostgreSQL (already set up; tables and sample doctors exist) |

Deploy the API first, because the website needs its address.

## 1. API on Render

`render.yaml` at the repo root describes the service.

1. Sign in at https://render.com with GitHub.
2. **New → Blueprint**, pick the `HeathCare-Plus` repo, then **Apply**.
3. Render asks for the values marked secret. Copy them from your local `backend/.env`:

| Key | Value |
|-----|-------|
| `DATABASE_URL` | Neon connection string |
| `FRONTEND_URL` | Your Vercel address, e.g. `https://healthcare-plus.vercel.app` (fill in after step 2; use `https://example.com` for now) |
| `GROQ_API_KEY` | Groq key |
| `SMTP_USER` | `healthcareplus.care@gmail.com` |
| `SMTP_PASS` | Gmail App Password |
| `EMAIL_FROM` | `HealthCare+ <healthcareplus.care@gmail.com>` |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google OAuth client |
| `GOOGLE_PLATFORM_REFRESH_TOKEN` | From `backend/.env` |

`JWT_SECRET` is generated by Render automatically. `NODE_ENV=production` turns off automatic table changes; to apply new columns after a code change, add `DB_SYNCHRONIZE=true` for one deploy, then remove it.

4. Wait for **Live**, then open `https://<your-service>.onrender.com/health`. It should say `"status":"healthy"`.

The free plan sleeps after 15 minutes without visitors; the first request after that takes 30 to 60 seconds.

## 2. Website on Vercel

1. Sign in at https://vercel.com with GitHub.
2. **Add New → Project**, import `HeathCare-Plus`.
3. **Root Directory**: `frontend`. Framework: Vite (detected). Build: `npm run build`. Output: `dist`.
4. Environment variable: `VITE_API_URL` = `https://<your-service>.onrender.com/api`
5. **Deploy**.

`frontend/vercel.json` sends every path to `index.html`, so links like `/doctors` work on refresh.

## 3. Connect the two

1. In Render, set `FRONTEND_URL` to the real Vercel address (no trailing slash) and save. Render redeploys.
   Extra addresses (custom domain, preview URLs) go in `CORS_ORIGINS`, comma-separated.
2. Open the Vercel site and check: doctor list loads, sign up, book an online appointment, AI chat replies.

## Google Meet in production

The refresh token in `GOOGLE_PLATFORM_REFRESH_TOKEN` works from any server. While the Google app is in **Testing** mode, Google expires it after 7 days. Before launch: Google Cloud → Google Auth Platform → Audience → **Publish app**, then run `npm run google-auth -- --print` locally and update the value in Render.

## Docker (optional)

`backend/Dockerfile` builds the same API image (`docker build -t healthcare-api backend`). Pass the same environment variables at run time.

## AI in production

Without `GROQ_API_KEY`, `/api/ai/status` reports the AI as unavailable and the chat shows labelled saved guidance instead. See [ai-integration.md](ai-integration.md).
